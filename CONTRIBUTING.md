# Разработка

## Начало работы

Нужны Python 3.10+ и Node.js 24 для полного набора проверок. npm-зависимостей нет. Если используется nvm: `nvm install && nvm use`.

Создайте ветку от актуального `main`: `git switch -c feat/short-description`. Для исправлений используйте `fix/...`, для документации — `docs/...`.

## Рабочий цикл

1. Запустите `python3 scripts/project.py dev`.
2. Меняйте файлы в `src/`. `dist/` — результат сборки, ручные правки будут потеряны.
3. При изменении структуры данных обновите `scripts/check-content.cjs` и `docs/content.md`.
4. Выполните:

```bash
python3 scripts/project.py check --require-node
python3 scripts/project.py test
python3 scripts/project.py build --require-node
```

5. Для UI проверьте ширины 360, 768 и 1440 px; Tab, Enter, Escape; отсутствие горизонтального скролла; открытие и закрытие карточек. При изменении ссылок проверьте реальные переходы. Для правок CSP проверьте консоль браузера через Caddy: dev-сервер не выставляет production-заголовки.
6. Откройте PR с описанием задачи, поведения и выполненных проверок. Визуальные изменения сопровождайте скриншотами.

Коммиты формулируйте по смыслу: `feat: add profile links`, `fix: preserve dialog focus`, `docs: clarify VPS setup`. Не смешивайте разные задачи в одном PR.

## Стиль

Два пробела в HTML/CSS/JS/YAML, четыре в Python; UTF-8 и LF. Настройки — `.editorconfig`. Внешние ресурсы, новые библиотеки и серверные сервисы добавляйте только с понятной причиной и описанием влияния на деплой.

Тесты нужны для контрактов и поведения, которое может сломаться: сборка, пути, структура данных, взаимодействия. Для небольшой правки текста достаточно существующих проверок и просмотра страницы.

## Перед публикацией

Используйте [чеклист персонализации](docs/content.md) и [инструкцию деплоя](docs/deployment.md). Доступы, `.env`, приватные фотографии и реальные секреты не коммитьте. Всё в `src/` станет общедоступным при размещении сайта.
