# Архитектура

## Текущее решение

Сайт полностью статический. Браузер получает `index.html`, `styles.css`, `content.js`, `app.js` с одного origin. Скрипты загружаются с `defer` в таком порядке: данные, затем приложение. `content.js` определяет `window.SITE_CONTENT`, а `app.js` создаёт карточки, заметки, контакты и модальные окна.

Внешних запросов, хранилища, cookies, трекинга и авторизации нет. Контакты — обычные ссылки, форма ничего не отправляет. Контент сейчас частично в `content.js`, частично в HTML; это явно отмечено в руководстве по редактированию.

## Каталоги и сборка

`src/` — единственный источник файлов сайта. `scripts/project.py build` проверяет исходники и копирует их в `dist/`, предварительно удалив прежний результат. Изменения в `dist/` не сохраняются и не попадают в Git.

Проверка выявляет дубли ID, отсутствующие локальные ресурсы, несуществующие HTML-якоря, выход ссылок за пределы `src/`, скрытые файлы и символические ссылки. Она не является полноценным HTML/CSS-валидатором и не заменяет браузерную проверку. Node.js проверяет синтаксис JS и контракт `SITE_CONTENT`; он не запускает браузер и не проверяет layout. В CI Node.js обязателен.

Сборка не минифицирует файлы и не генерирует хеши имён: файлы малы, Caddy сжимает ответы, агрессивный immutable cache не включён. Если появятся большие медиа или много страниц, можно добавить отдельную обработку ресурсов.

## Границы инструментов

Python нужен разработчику и CI, но не VPS в Docker-варианте. Node.js нужен только для проверок JavaScript. Production — один контейнер Caddy, volume с готовым `dist/` и постоянные volumes для сертификатов и конфигурации.

`Caddyfile` задаёт CSP для ресурсов с того же origin; favicon допускается через `data:`. Inline-скрипты и стили не используются. Динамические тексты попадают в DOM через `textContent`; `innerHTML` применяется только для трёх постоянных иллюстраций из кода приложения.

## Когда менять архитектуру

- Много статей, RSS и отдельные адреса заметок: рассмотреть статический генератор, сохранив простой VPS-деплой.
- Редактирование без Git: отдельно выбрать CMS и схему публикации.
- Формы, аккаунты, приватные данные: спроектировать backend и хранение, пересчитать ресурсы VPS.

До появления таких задач фреймворк и база данных не требуются.
